## 实际调用和配置

当前旧项目链路：

```text
off_task_control_service.start_mining_task
  → sys.executable 启动具体控制器
  → 选择实际业务config
  → 入库子进程 search_index_data_interface.py insert_data_to_search_index
  → SearchDataInterface(config_path=业务config)
  → load_search_engine(业务config.search_engine_config_path)
  → EsSearchInterface真实工厂 → EsSearchInterfaceES8 → IndexClientRouter
  → process_one_data → engine.insert → client.update(doc=..., doc_as_upsert=True)
```

知识生成任务直接走批量CLI，**不经过 `/insert` 检索服务API**，因此改检索服务启动时的配置参数不会自动改变这些任务。

| 任务/阶段 | 优先业务配置 | 后备配置 | 入库解释器 |
|---|---|---|---|
| 文档QA，stage7 | `<index_name>_config.json` | config_for_search_index.json → index_config.json | PATH中的 `python` |
| 文档QA+segment，stage8/11 | 同上 | 同上 | PATH中的 `python` |
| HTML QA+segment，stage8/11 | 同上 | 同上 | PATH中的 `python` |
| 聊天QA，stage5 | `<client>_config.json` | 同上 | PATH中的 `python` |
| Excel上传，stage3 | `<index_name>_config.json` | 同上 | 控制器的 `sys.executable` |

路径均位于任务的 `script_dir/config/`。存在专用配置时优先使用，换通用文件不会覆盖其指向。聊天配置按client选择，实际目标仍取index_name/index/client，不要把二者混为一谈。几个控制器还会缓存选中的文件路径，但没有缓存这个文件的全部engine配置。

sg检索服务启动参数使用 `config/config_for_search_index_es817.local.json`，它指向 `config_es_engine_es817.old.local.json`。sg离线默认仍选 `config/config_for_search_index.json`，它指向 `config_es_engine.json`；没有任何逻辑自动改选名字带es817的文件。

真正切换要修改**离线任务实际选中的业务配置**及其engine配置指向。engine当前使用明确的 `"es_version":"8.17"`、两provider地址/认证、原索引名的index_routes，以及与embedding一致的1024维配置。只换hosts不充分：当前旧工厂自动检测收到8.17版本仍走es7兼容模式，必须显式指定8.17。此为必要配置前提，已通过真实检测helper的离线响应验证，未访问旧ES。

每个新启动的入库CLI会重新加载配置；在运行批次里已构造的client不会因改文件而自动换库。已有离线实例的新CLI阶段读取同路径新内容的行为已测试，不需要额外上层API或改变index请求名；不能据此声称正在运行的所有阶段都支持配置热切换。
