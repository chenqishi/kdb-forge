# forge独立协议薄适配

范围：保留原kdb.api启动名、路由、Basic/字段/响应及modify计划模型；业务委托唯一SearchDataInterface和已发布引擎。

KnowledgeService.from_config只转换原forge配置指针，保留default_index_name/test_index_name优先级；计数入口复用原get_from_type_count，按forge响应协议包装tuple，不另建统计算法。

KnowledgeService公开构造恢复原repository、embedding_client、default_index、multimodal_prefix、check_duplicate、is_need_llm、simility_tools、category_client及keyword-only legacy_config。第五位置Mapping按原协议接收，与keyword配置冲突仍TypeError；显式开关覆盖配置。初始化公开状态由同一个SearchDataInterface对象承载，不运行其真实配置初始化；公共状态赋值保持委托对象同步。内部已构造的interface使用_from_interface工厂，与公开旧签名区分。

KnowledgeRepository保留原engine首位置参数、配置工厂、default_index回退及缺少依赖ValueError。正式薄模块位于forge_compat/repository.py，原kdb.crud.repository是同一模块对象别名，保留公开导入及monkeypatch行为，不改公开包导入时机来绕开循环。

Repository原纯委托文件整体保留，构造及12项公开方法完整承接：count_by_query(index_name,query)强制require_complete=True，ensure_index、insert、update_by_id、update_by_condition、get_client_by_index、delete、get、search、search_multi、search_by_page、get_unique_values均保留原参序/默认/返回与刷新，整个文件字节及类AST与原源相同；没有第二套ES引擎。

search_text/search_text_multi/web_search及对应search_data_by_query/search_data_by_multi_query/web_search_data旧名均保留原参数；列表仅在协议边界转成核心接受的逗号格式，不改核心。查询与web保持各自原默认索引语义；类别转接在调用时读取当前_category，后赋值注入生效。get_from_type_count恢复原index_name/start/end/from_type位置顺序，继续委托原计数接口。

SearchDataInterface、ID、embedding和引擎符号直接转发。KnowledgeRepository仅做既有参数名称转接，不含检索/评分/查重。CategoryClient保留service_url/update_interval及公开缓存属性，全部树/TTL方法转到同一正式类；没有复制第二套类目缓存算法。

forge独有更新保留原update、_sync_retrieval_indexes和_regenerate_embeddings三个方法，方法AST与原内容快照严格相同。默认regenerate_embedding=False；显式True时重算传入文本及indexes向量，标题/同义词变动时读取旧文档同步检索项，保留自定义和图片项，始终刷新update_time并剔除payload中的_id。缺少必要旧文档或embedding失败仍按原语义报错。数据库读写经薄KnowledgeRepository委托唯一已发布引擎，不复制第二套ES实现。

refresh=True只在更新成功后刷新；刷新异常按原协议记日志、不改变已成功更新的返回值。apply_modify_plan原函数不变，逐条收集成功/失败，失败后仍继续后续更新及允许的插入；dry_run不读库、不重算或写入。新增主动禁用已撤销并作偏离记录。旧12接口不走此适配，原Dify工作流完整保留。

网络/数据库方法只在原请求触发时委托；本批没有实测真实外部写入。独立forge调用方和内部构造兼容未全部盘点，不能据线协议smoke声称全部后台语义等价或允许上线。
