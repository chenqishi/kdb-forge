# 附加判定规则（joint_login 专用，优先级高于以上任何规则）

这批 QA 来自跨境电商服务商的群聊，最主要的质量问题**不是表达不清，而是「只对某一个具体案例成立」**。
判定时请优先检查下面三条，命中就不能给 #优质。

## 1. 个案专属 → #不通用

问题或答案中出现下列任一种，即为个案专属：

- 店铺代号：`BR0751H-LT`、`GR0035`、`NK0029` 这类字母数字组合的店铺/客户编号
- 具体公司名：`VERO VIDE ACESSORIOS LTDA`、`嘎达贸易` 等指向某一主体的名称
- 具体人名、税号、账号、订单号、PIX/收款账号
- 具体金额或余额：`3210.07巴币`、`82413.01`
- 只是在同步某一单据/某一店铺的当前状态，换个店铺就不成立

标 `#不通用`。这类 QA 即使表述清楚、答案完整，也**不算优质**。

示例：
- `问题:BR0576F-SL:嘎达贸易-D.A. STORE LTDA 金额是多少？ 答案: 3210.07巴币` → `#不通用#不相关`
- `问题:公户下来了吗 答案: null 来源:` → `#无实质答案#不清晰`

## 2. 内部转派口吻 → #需要修改

答案以「告知他…」「回复客户说…」「让他去…」「跟他讲…」开头或通篇是指挥同事怎么答，
而不是直接回答提问者，标 `#需要修改`。

示例：
- `答案: 告知他8月起 数据同步后，该模式一旦给稽查风险自行承担，建议更换合规模式；` → `#需要修改`

## 3. 问答同句复述 → #无实质答案

答案只是把问题原样重复一遍、没有增加任何信息，标 `#无实质答案`。

示例：
- `问题:邮箱转账功能是你们可以开通的吗？ 答案: 邮箱转账功能是你们可以开通的吗` → `#无实质答案`

## 4. 主体指代不清 → #不清晰

问题里用「这个/这家/该/上面那个」指向一个**没有在问题中说明的主体**，
读者单看这条 QA 不知道在问谁，标 `#不清晰`。

示例：
- `问题:这个店铺最迟什么时候清完库存？` → 哪个店铺没说 → `#不清晰`
- `问题:那这个主体的费用是否收费` → 哪个主体没说 → `#不清晰`

注意与第 1 条的区别：这里是**该说明却没说明**，第 1 条是**说明了但只对这一个案例成立**。
两者都不能给 #优质。

## 5. 什么才算 #优质

同时满足才给 `#优质`：

- 换一个店铺、换一个客户，这条知识**依然成立**
- 答案是直接、完整、可独立看懂的回答，不依赖上下文
- 内容属于政策规则、操作流程、判断标准、原因解释或方案建议之一
- 不含任何个案标识（店铺代号/公司名/人名/金额/单号/账号）

宽松打分比漏标更有害：不确定是否通用时，标 `#不通用` 而不是 `#优质`。
